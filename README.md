# Скринер облигаций РФ (MOEX)

Веб-скринер облигационного рынка России: фильтры, сортировка, готовые
стратегии, расчёт дюрации и спреда к кривой ОФЗ, конструктор портфеля
по календарю выплат с автосборкой под бюджет, выгрузка в CSV. Все данные
берутся напрямую с **MOEX ISS API** — бесплатно и без ключей.

**Публичная версия:** <https://macromax2.github.io/bond-screener-rf/>
(статическая сборка с GitHub Pages, данные в браузер подгружаются из
`data.json` — формат тот же, что у `/api/screener`).

> Проект живёт в отдельной папке `screener/` и не связан с конвейером постов
> в корне репозитория.

## Быстрый старт

```bash
cd screener
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# запуск (лучше через скрипт — процесс переживает закрытие терминала)
./run.sh              # старт на http://127.0.0.1:8000/
./run.sh status       # проверить
./run.sh stop         # остановить
./run.sh restart      # перезапустить

# либо напрямую
.venv/bin/uvicorn app.main:app --port 8000
```

Открыть <http://127.0.0.1:8000/> — интерфейс скринера.

Проверка ядра без сервера:

```bash
.venv/bin/python -m app.selftest          # собрать снапшот за закрытый день
.venv/bin/python -m app.selftest --db     # проверить сохранённый снапшот
```

## Как обновляются данные

Скринер устроен вокруг **дневного снапшота** — состояния рынка за последний
**закрытый** торговый день.

Почему не live-данные: утром до открытия биржи (10:00 МСК) у биржи оборот
дня ещё нулевой. Если строить скринер на живом снапшоте, ликвидность всех
бумаг падает в 0, и пресеты с фильтром ликвидности (а это почти все)
становятся пустыми — вечером работают, утром нет.

Поэтому раз в день после закрытия основной сессии скринер:

1. берёт статичные параметры выпусков и текущие доходности/дюрацию
   (`markets/bonds/securities`);
2. дозагружает **итоги закрытого дня** из истории торгов
   (`history/.../securities`): оборот, число сделок, средневзвешенную цену
   и доходность — они за полный день и не обнуляются к утру;
3. сохраняет снапшот в **SQLite** (`data/screener.db`).

Дальше сервер просто отдаёт последний снапшот из базы — мгновенно и
предсказуемо в любое время суток, 24/7. Утром, ночью и в выходные видны
полные данные закрытого дня, и время обновления не влияет на полноту.

- **Время пересборки:** 19:05 МСК (после закрытия основной сессии 18:40).
  Настройка — константа `UPDATE_AT` в `app/main.py`.
- **Планировщик** работает внутри процесса сервера. Если обновление пропущено
  (ноутбук спал или хостинг «засыпал» при простое), сервер догоняет его при
  старте — сверка даты последней сборки с ближайшим закрытым днём
  (`_catch_up_if_missed`), — а затем штатным проходом цикла.
- **Холодный старт в облаке:** если база пуста, сервер собирает снапшот
  в фоне сам (~2–4 минуты); первый посетитель видит в шапке сообщение
  «первичная сборка…», страница обновляется сама после готовности.
- **Вручную:** кнопка «↻ Обновить» или `POST /api/refresh` — сборка в фоне,
  ~2 минуты (история по 9 доскам с пагинацией по 100 строк).
- **Хранение:** 30 дневных снапшотов, старые чистятся автоматически
  (`store.KEEP_DAYS`). База растёт примерно на 0.3–0.5 МБ в день.

## Публичная версия (GitHub Pages)

Скринер живёт на бесплатном хостинге **GitHub Pages**:
<https://macromax2.github.io/bond-screener-rf/>

Устройство:

- **`static/index.html`** умеет работать и с сервером, и без него. Если
  `/api/screener` недоступен (404 на статическом хостинге), страница сама
  переключается на **`static/data.json`** — тот же JSON-ответ, что отдавал
  сервер. Кнопка ручной пересборки в этом режиме скрывается.
- **`app/export.py`** собирает `data.json` из той же базы и теми же функциями,
  что и ответ API (`_facets` / `_stats` / `_human_date`), поэтому формат
  полностью совпадает. Запуск: `.venv/bin/python -m app.export`
  (`--if-stale` — пересобрать, только если снапшот устарел).
- **`publish.sh`** выгружает `static/` (index.html + data.json) в ветку
  **`gh-pages`** и пушит её; GitHub Pages пересобирает сайт за ~1 минуту.
  Если содержимое не изменилось — пуш не выполняется.
- **Автопубликация.** Сервер (`app/main.py`) сам вызывает `publish.sh` после
  каждой пересборки снапшота (19:05 МСК, ручное обновление, догон при старте),
  поэтому публичная версия обновляется тем же расписанием, что и локальная.
  Запуск вручную: `./publish.sh`.
- **Обновление интерфейса:** правка → `git push` в `main` → `./publish.sh`
  (или дождаться авто-публикации) → сайт обновляется через минуту.

Старая облачная схема (FastAPI-сервер: `Dockerfile`, `render.yaml`) сохранена
в репозитории и работает локально; публичная версия статична и не требует
ни карты, ни сервера — только git-push.

## Что умеет

- **Три отдельных экрана** с переключением вкладками в шапке (на телефоне —
  закреплённой нижней панелью): «Таблица» (фильтры и скрининг), «Календарь»
  (купоны по выборке за месяц) и «Портфель» (конструктор и автосборка).
  Последний открытый экран запоминается между визитами.
- **Фильтры** — тип бумаги (ОФЗ / субфедеральные / муниципальные / корпоративные /
  биржевые), доходность YTM, остаточный срок, цена, дюрация, спред к кривой ОФЗ,
  тип купона, валюта номинала, ликвидность, оборот, фактор сложности 0–7,
  «торговались сегодня», налоговая льгота 3+ года, поиск по тикеру / ISIN /
  названию / эмитенту.
- **Сортировка** по любой колонке (клик по заголовку).
- **Стратегии-пресеты** (по мотивам ДОХОДЪ): альтернатива депозиту, сбалансированный,
  high yield, короткие, лонг-фикс, только ОФЗ, налоговая льгота, ежемесячный купон.
- **Конструктор портфеля** — сборка по календарю купонов: 12 месяцев с подсветкой
  выплат, фильтр Все/Фикс/Плав, целевое число месяца («получать 10-го»), бюджет
  со «сдачой» (сколько лотов влезает и сколько остаётся), купонный график
  календаря по выборке.
- **Автосборка под бюджет и цель** — кнопка «🤖 Автосборка» подбирает 3–6 бумаг
  (для цели «выплаты каждый день» — до 30) из текущей выборки: фильтры блока 1
  работают как ограничения, амортизация исключается, нормируются лоты.
  Цели: «ровный доход» (все месяцы закрыты, минимум неровности),
  «выплаты каждый день» (максимум дней с выплатами), «максимум доходности»,
  «только госбумаги». Лимиты: не более 2 бумаг одного эмитента (госбумаги
  вне лимита) и не более 40% бюджета на эмитента, «стресс-коридор» по
  доходности (бумаги с дефолтными ожиданиями не берутся), только бумаги
  с положительной доходностью и живой торговлей. Всё считается на клиенте,
  ~50 мс (цель «выплаты каждый день» — ~0.5 с из-за 30 бумаг).
- **Карточка бумаги** — все параметры, квал-статус, дефолты, история цены и
  доходности за 180 дней.
- **CSV-экспорт** отфильтрованных строк (открывается в Excel, BOM + `;`).
- **Налоги** — YTM после НДФЛ 13%/15% и пометка кандидатов на льготу 3+ года.

## Архитектура

```
screener/
├── app/
│   ├── moex.py        # низкоуровневая загрузка MOEX ISS (снапшот, каталог, кривая, карточка, история)
│   ├── daily.py       # сборка дневного снапшота: live-параметры + итоги закрытого дня
│   ├── store.py       # SQLite-хранилище дневных снапшотов (data/screener.db)
│   ├── analytics.py   # расчёты: YTM, дюрация, ликвидность, сложность, налоги, пресеты
│   ├── main.py        # FastAPI-сервер: маршруты, планировщик 19:05 МСК, facets/stats, CSV
│   ├── export.py      # выгрузка снапшота в static/data.json (для GitHub Pages)
│   └── selftest.py    # автономная проверка ядра
├── static/index.html  # веб-интерфейс (тёмная тема, canvas-графики, без сборки)
├── data/              # база снапшотов + кэш каталога (создаётся автоматически)
├── run.sh             # запуск/остановка процесса (nohup, переживает терминал)
├── publish.sh         # публикация static/ в ветку gh-pages (GitHub Pages)
├── requirements.txt   # fastapi, uvicorn
└── README.md
```

### Источники данных (MOEX ISS, все бесплатные)

| Эндпоинт | Что даёт |
| --- | --- |
| `engines/stock/markets/bonds/securities` | все выпуски разом: статика, котировки, доходности, дюрация, Z-spread (~4 МБ) |
| `history/.../boards/{board}/securities?from=&till=` | **итоги дня**: оборот, сделки, WAP, доходность, дюрация (пагинация по 100) |
| `securities?engine=stock&market=bonds&is_trading=1` | тип бумаги, эмитент, ИНН, ISIN (каталог, пагинация) |
| `engines/stock/zcyc/securities` | кривая доходности ОФЗ + эталонные выпуски |
| `securities/{secid}` | квал-статус, частота купона, дефолты (лениво, по клику) |
| `history/.../boards/{board}/securities/{secid}` | история бумаги для графика (лениво) |

Доски в скринере: `TQCB, TQOB, TQOD, TQOE, TQOY, TQRD, TQIR, TQNB, TQNO`.
Дубли SECID между досками разрешаются приоритетом списка; `SPOB` пропускается
(дубль основной доски ОФЗ).

### Хранилище и обновления

- **Дневные снапшоты** — SQLite `data/screener.db`, таблица `snapshots`
  (JSON-массив записей, сжатый gzip). Хранится 30 дней, старые чистятся.
- **Планировщик** — фоновый поток внутри сервера, пересборка ежедневно в
  19:05 МСК. Пропуск (спал ноутбук) догоняется на следующем проходе.
- **Каталог** (типы бумаг, эмитенты) — кэш на диске `data/catalog.json`,
  24 часа; перезагружается при `force`-обновлении.
- **Ручное обновление** — кнопка «↻ Обновить» / `POST /api/refresh`, сборка
  в фоне (~2 мин).

## Методика расчётов

- **YTM** берётся из расчёта биржи (`EFFECTIVEYIELD` → `EFFECTIVEYIELDWAPRICE` →
  `YIELDATWAPRICE` → `YIELD` → `YIELDATPREVWAPRICE`). Если биржа не посчитала
  (нет сделок), используется собственное приближение (`yield_to_maturity`).
- **Дюрация** — из `marketdata_yields.DURATION` (ISS отдаёт в днях; делим на 365.25).
- **Спред к кривой ОФЗ** — интерполяция кривой ZCYC по остаточному сроку,
  вычитается из YTM (только для рублёвых бумаг).
- **Ликвидность 0–100** — авторский балл: логарифм оборота за день, бонус за
  число сделок, штраф за широкий спред (упрощённая аналогия ДОХОДЪ).
- **Фактор сложности 0–7** — по мотивам ДОХОДЪ: 0 простая, 1 PUT, 2 амортизация,
  3 плавающий купон, 4 линкер, 5 CALL, 6 вечная/конвертируемая, 7 структурная.
- **Аномальные доходности** (YTM > 600% или < −50%) помечаются флагом и
  исключаются из статистики, графиков и пресетов по умолчанию — обычно это
  бумаги у погашения или без сделок.

## Ограничения (v1)

- Нет рейтингов агентств: MOEX ISS не отдаёт кредитные рейтинги, а бесплатные
  источники (рейтинговый реестр ЦБ, Эксперт РА, НКР, АКРА) отвечают капчей,
  ошибками или грузят данные через AJAX. Поэтому рейтинги выводятся только из
  ТИПА ЭМИТЕНТА (ОФЗ → ruAAA, субфед → ruAA, муниц → ruA, корпоративы → нет),
  а фильтр в интерфейсе честно называется «Только госбумаги (ОФЗ/субфед/муниц.)»
  и проверяет тип эмитента, а не мнимый рейтинг. Подключение реестра из
  НКР/Эксперт РА предусмотрено точкой входа `ratings.fetch_external()`.
- Квал-статус и история подгружаются лениво при открытии карточки, а не в
  общем снапшоте (иначе пришлось бы делать ~3000 лишних запросов).
- Расчёт YTM для бумаг без сделок — приближённый, не точный к погашению.
